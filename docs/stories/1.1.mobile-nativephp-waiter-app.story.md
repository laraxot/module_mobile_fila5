# Mobile NativePHP Waiter App - BMAD Story

## Story Overview

**Target:** The restaurant app now includes a dedicated **Mobile NativePHP Waiter App** that empowers waiters to take orders directly from their smartphones and tablets, revolutionizing the dining experience with a native, high-performance solution.

**Problem Solved:** Traditional restaurant ordering systems require waiters to carry multiple devices or rely on slow web-based interfaces. The solution provides a seamless, offline-capable mobile experience with real-time kitchen integration.

## Architecture Decisions

### **SuperNative (PHP binary + native Swift/Kotlin shell)** 
**NOT web-based**

**Why:** 240fps, no web view, native performance, works offline

**Key Benefits:**
- **240fps performance** for smooth animations and gestures
- **No web views** = true native experience
- **Offline-first** capability for reliable service in poor connectivity areas
- **Native camera** integration for QR scanning
- **Haptic feedback** for responsive interactions

**Implementation:**
- NativePHP bridges PHP backend with native mobile shells
- Direct native API calls for device features (camera, GPS, haptics)
- Zero-latency UI rendering through native components

### **Communication with Restaurant Module**
**Authenticated HTTP bridge**

**Why:** Secure data exchange while maintaining module isolation

**Architecture:**
- **Filament panel serves as API** for all mobile requests
- **Token-based authentication** for secure session management
- ** RESTful API endpoints** with Sanctum authentication
- **WebSocket support** for real-time updates (KDS notifications)

**Security:**
- Role-based access control
- Session tokens with expiration
- Request validation and rate limiting
- Encrypted payload transmission

## Development Principles

### **No HTTP Controllers → use Folio pages + Actions**
- All logic in Spatie QueueableAction classes
- Folio pages for Filament integration
- Clean separation of concerns
- Testable, maintainable code

### **No Services → use Spatie QueueableAction**
- Each action is async and queueable
- Idempotent operations
- Retry logic and error handling
- Background processing

### **declare(strict_types=1)**
- PHP type safety
- Static analysis compliance
- IDE autocompletion
- Runtime type enforcement
